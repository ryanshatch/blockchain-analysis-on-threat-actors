# Repository security review — September 8, 2026

## Result and scope

**No confirmed malware, backdoor, shipped CSV formula payload, or repository-provided clone-time RCE path was found.** The review identified a conditional formula-injection exposure in the export helpers, a local overwrite hazard, external resource loading in the legacy FTX stylesheet, and an unresolved dependency-version risk. These observations are not evidence that the repository has been compromised.

Every one of the **109 tracked source files** was read and parsed after the Liquid attribution correction. The source snapshot comprises **6,828,116 bytes**, based on `main` commit `6a14083ddb1ac5831a373fc6859063d121eed725`, with corrected source tree `4e3af1ab7c77d3392eedca00ecf530e05c0acc8b`. The [file inventory](./2026-09-08-files.json) records each path, byte count, SHA-256, Git blob, inspection method, and result. These two audit records were additionally checked as inert Markdown and JSON; they are excluded from the source inventory to avoid self-referential hashes.

## Findings

### SR-01 — Conditional formula-injection exposure in file exports

**Severity: Medium, conditional on importing untrusted output as formulas. Confidence: High in the unsanitized export behavior.**

Files and locations:

- [`parsing/visual_of_data_loss.py`](../../parsing/visual_of_data_loss.py), lines 88–97: selected file contents are split into lines, placed in a DataFrame, and passed directly to `to_csv()`.
- [`parsing/merge_files.py`](../../parsing/merge_files.py), lines 84–89: selected file contents are copied verbatim into the combined output.

**What the files do:** both are local Tkinter file-merging tools. The visualizer exports CSV-formatted data under a `.txt` extension and displays a missing-data heatmap. The simpler merger writes the input text directly. Neither tool neutralizes a spreadsheet formula supplied in an input file.

**Trigger:** a person runs a helper, selects attacker-supplied input containing formula text, exports it, and later opens/imports that output in a spreadsheet with settings that interpret the content as formulas. The harmless test string `=1+1` survived the visualizer's DataFrame-to-CSV operation unchanged in an independent pandas 2.2.3 check. Merely downloading or cloning the repository does not invoke this path.

**Potential effect:** formula evaluation, deceptive cells or links, or data disclosure through supported spreadsheet functions. Command execution would require additional conditions, such as vulnerable spreadsheet software or an enabled external-command feature. No RCE was demonstrated and no formula payload was found in any shipped CSV or text export. [OWASP's CSV-injection guidance](https://owasp.org/www-community/attacks/CSV_Injection) describes these application-dependent conditions.

**Suggested remediation:** separate raw evidence exports from spreadsheet-safe exports; write untrusted strings as explicit text or use a validated sanitization policy for the target spreadsheet application. CSV quoting alone does not make formula text inert. Preserve original indicators in the raw dataset and test the safe export with a harmless formula canary.

### SR-02 — Output overwrite can destroy a selected input

**Severity: Low; local data-loss hazard. Confidence: High.**

Files and locations:

- [`parsing/merge_files.py`](../../parsing/merge_files.py), lines 82–86.
- [`parsing/visual_of_data_loss.py`](../../parsing/visual_of_data_loss.py), lines 85 and 97.

The GUI's output-name text becomes a path with `.txt` appended. Both writers overwrite an existing destination without an overwrite confirmation or input/output collision check. In `merge_files.py`, the destination is opened in write mode **before** the selected inputs are read. Selecting an existing text file and choosing that same path as the output can therefore truncate the input before the tool reads it.

This requires local use of the GUI and permission to write the chosen path. It is not a remotely exposed arbitrary-file-write service and does not run during cloning.

**Suggested remediation:** resolve and compare input/output paths, reject collisions including symlink aliases, confirm replacement of existing files, and write to a temporary file before an atomic replacement.

### SR-03 — Legacy FTX HTML loads external resources

**Severity: Low; privacy and external-content dependency. Confidence: High.**

[`FTX/resources/sheet.css`](../../FTX/resources/sheet.css), line 2, imports a Google Fonts stylesheet. The CSS contains **352 remote URL references**: one at `fonts.googleapis.com`, 349 at `ssl.gstatic.com`, and two at `fonts.gstatic.com`. These are references, not a count of requests a browser will necessarily make.

[`FTX/Alameda.html`](../../FTX/Alameda.html) and [`FTX/FTX.html`](../../FTX/FTX.html), both line 2, load this local stylesheet. Opening them in a browser can therefore fetch fonts and applicable image resources, exposing ordinary request metadata to those services and depending on remotely changeable resources. No malicious JavaScript, event handlers, or data-exfiltration routine was found in either HTML file.

The base64 assets were also checked: **71 embedded images** across the stylesheet and root README, comprising 51 SVGs and 20 PNGs. Their decoded content contained no scripts or active SVG constructs. Apparent `behavior:` matches were ordinary `overscroll-behavior` / `scroll-behavior` properties, and a `fetch` match was a CSS class name.

**Suggested remediation:** if offline viewing is desired, replace the exported stylesheet with the small set of local styles actually used by these two tables, or host the required assets locally.

## CVE and dependency assessment

There is no requirements file, lockfile, package manifest, vendored Python dependency, or declared installed-version inventory in the source tree. The helpers import `python-docx`, and the visualizer additionally imports pandas, Matplotlib, and seaborn. A complete installed-dependency CVE assessment cannot be established from this repository alone. Versions installed in the review environment are not evidence of the versions installed on a reader's computer.

| Item | Applicability to this repository |
|---|---|
| **CVE-2016-5851 — python-docx XML external entities** | A relevant **conditional exposure**, not a confirmed vulnerable installation. Both helpers parse user-selected DOCX files through `Document(file_path)`. Versions before 0.8.6 allow XXE through crafted documents; 0.8.6 disabled entity expansion. The repository neither bundles a DOCX payload nor specifies a vulnerable version. Use a maintained patched dependency before processing untrusted documents. [Upstream change history](https://github.com/python-openxml/python-docx/blob/v0.8.6/HISTORY.rst), [advisory and version range](https://github.com/advisories/GHSA-34wj-p5jm-2p96) |
| **CVE-2024-32002 — Git recursive-clone hook execution** | No matching repository payload was found: the tree has no submodules, symlink entries, or `.gitmodules`. All 109 entries are regular `100644` blobs. This does not assess the user's Git installation or every historical Git vulnerability. [Git's official advisory](https://github.com/git/git/security/advisories/GHSA-8h77-4q3w-gfgv) |
| Installation instructions | [`parsing/readme.md`](../../parsing/readme.md), line 19, and [`parsing/sol tx history/readme.md`](../../parsing/sol%20tx%20history/readme.md), line 18, use unpinned `pip install` instructions and list `tkinter` as a pip dependency. Tkinter is Python's Tcl/Tk interface and should be supplied through the supported Python/OS installation. This is an installation-quality issue, not evidence of a malicious package. [Python documentation](https://docs.python.org/3/library/tkinter.html) |

## Notable negative results

- **All 48 CSVs:** zero formula-injection candidates. The scan covered 443 nonblank data rows plus headers; three CSV files have an extra blank record, a formatting issue without an execution path. No hidden executable file masquerading as CSV was found.
- **`FTX/FTX_DB.xlsx`:** two visible sheets, 37 formula cells including shared-formula followers. The formulas perform subtraction, division, and sums. No VBA, XLM macro sheets, ActiveX, OLE packages, external links/connections, hidden sheets, defined names, or appended ZIP payload was found.
- **`SOL/HOPE/current_stats.pdf`:** seven printed portfolio-dashboard pages. No JavaScript, OpenAction, additional actions, Launch, embedded files, external URI actions, forms, or appended payload was found. The parser reported noncanonical whitespace in object headers; a second PDF utility and page rendering succeeded, with no associated active-content finding.
- **All four PNGs:** complete image decoding and chunk checks succeeded. No appended payload or suspicious text metadata was found. The historical Matplotlib version in one image's metadata identifies its generator, not an installed dependency or executable component.
- **`scammer DB.html`:** a list of `mailto:` links. Clicking one can open an email-composition window; it does not automatically send email or execute a repository script. These are threat-intelligence contact indicators, not a malware payload.
- **Repository configuration:** no Actions workflows, install hooks, submodules, symlinks, LFS pointers, native executables, or repository-supplied code-execution Git filters were found. Ordinary client-side hooks are not copied from a remote repository when it is cloned. [Git documentation](https://git-scm.com/book/en/v2/Customizing-Git-Git-Hooks)
- **Python execution:** the two GUI scripts run only when explicitly executed or imported. Their source contains no shell execution, dynamic evaluation, network client, credential-stealing routine, or unsafe pickle deserialization. SQL and XML inputs in their ordinary text branches are read as text, not executed.
- **Threat reports and indicators:** exploit descriptions, attacker addresses, and defanged phishing domains were treated as evidence data. No runnable exploit implementation was found in the source tree.

## Limits and disposition

This is a static content review with complete file coverage for the recorded source snapshot, not a guarantee that every possible parser vulnerability, steganographic payload, future dependency compromise, or unknown malware family is absent. No antivirus signature engine or sandbox detonation service was available or used. The review did not fetch the targets of threat-intelligence links, execute the GUI programs, install their dependencies, inspect the user's device, or review every historical commit and branch.

The Liquid report, address roles, partial-return transaction, and indexes were updated. The existing helper code and legacy exports remain unchanged; the findings above document their behavior and remediation options for review.
